# Token Art log: 2026-10

The dated journal of this repo, moved out of `CLAUDE.md` (which keeps the rules and one State block). One
heading per day, oldest first; each entry keeps its facts as written at the time. Release detail is on the
GitHub release notes.

## 2026-10-15

- **The decisions** (the plan's D1–D4, `../docs/plans/tokenart.md` in the suite) were taken this day. D4, the
  name: Token Art was free on the setup screen's package list on 2026-10-15 (6,988 modules; neighbours Show
  Token Art, Token Variant Art, Automatic Token Image, Token Alt Image Toggle, Update Token Image).
- **Built from the plan**; `npm run verify` green (58 tests); deployed to the sandbox with the dnd5e MCP's
  `deploy-house-module.mjs --local`, registered there by a restart of the local Foundry process (a new module's
  folder is scanned at process boot), enabled, and walked: all twelve steps of `tools/README.md` green (the
  results are under the list; step 12's "then disabled" half failed on the first build and passed on the
  world-pause build, re-run after the By the Books battery that held the sandbox meanwhile). The walk changed
  the build four times: decisions read the token's stored image (`_source`), never the prepared one, since
  Foundry animates a texture change and the prepared `texture.src` lags the source; Rescan rides a hidden world
  setting so any GM window's press reaches the active GM; a token found wearing a look-shaped image with no flags
  is recognised as that look when the base file exists (dnd5e's `revertOriginalForm` hands the stored image back
  and drops every flag); and Restore All pauses the whole world, not one client, since the MCP's
  `configure-modules.mjs` page is a GM client that runs the module.
- **Released as 1.0.0** (tag `v1.0.0` at 110d743, the zip and `module.json` on the release) and installed on
  prod the same day through Foundry's installer (`register-module.mjs` from the GitHub manifest, a new module
  needs `/setup`'s `installPackage`, never a world bounce), then `configure-modules.mjs --enable` and a second
  installer run as the bounce; the DM's own window was the one connection dropped. The sandbox runs the same
  bytes as a dev copy (`--local`). The sandbox was left with the module enabled and unpaused, Party Camp active,
  the walk's scenes deleted, no combats and no Token Art flags on any token; the walk's art stays under
  `assets/tokenart-walk/` (nine small PNGs: `x.png` and its four looks, and a `wild/` folder) for trying the
  module. The BTB test actors the walk borrowed were gone by then, torn down by the battery, so nothing of theirs
  needed restoring.
- **1.0.1 the same day**: a correctness review by a session that did not build it, with an independent second
  read beside it, found fifteen things, all fixed (`audits/review-2026-10-15.md` has each with its fix; the
  design points it left are the repo's issues #1–#4): the wildcard filter kept a look whose base the wildcard
  never matched (`goblin-*.webp` lists `goblin-dead.webp`, never `goblin.webp`; `lookCandidatesOutside` plus one
  cached probe of the candidate base, GM clients only, settles it); a change of the separator setting adopted a
  worn look as a new base (`baseOf` recognises the look the flags name under every separator); Restore All put
  the flagged base over an image the module never adopted (`restoreUpdate` restores only from the base's own
  looks); Restore All raced an in-flight batch (the seat and the pause are re-checked before each scene's write;
  `restoreAll` awaits the chain); a Rescan during a running reconcile was swallowed (`reconcileAll` queues one
  more pass); a stale plan overwrote a concurrent image change, and a token deleted meanwhile failed its scene's
  whole batch (`stillCurrent` drops both before the write); the ring subject dnd5e's revert hands back was
  adopted as a base of its own (`resolveBase` for the subject too), and Restore All with the ring off left the
  subject's look stored (`stored().subjectSet`); `updateCombatant` and `createScene` are heard; a world actor's
  unlinked tokens follow its edits; `tokenart.changed` fires only when the image changed; and every `-=`
  deletion key becomes a `ForcedDeletion` operator on Foundry 14, which logs a compatibility warning on every
  legacy key and drops them in 16 (`withDeletionOperators`; 13 keeps the keys). `npm run verify` green (73
  tests). The three live checks owed (a back-to-base swap, Restore All then Rescan, the wildcard with an
  unmatched base) ran green on the sandbox through a GM page script with the console captured, zero
  deletion-key warnings; the check's first run taught that a fresh NPC with no Hit Points sits at 0 and wears
  its dead look (D1). Released as **1.0.1** (tag `v1.0.1`, both assets on the release, the zip built from the
  tag with LF endings so a byte-identical check against the repo holds) and installed on prod through the
  installer the same evening (`register-module.mjs` from the GitHub manifest; the DM's own window was the one
  non-bridge connection dropped, on the user's word; read back `installed v1.0.1 (active=true)` with
  `configure-modules.mjs --dry-run`); the sandbox carries the same bytes (`--local`).
